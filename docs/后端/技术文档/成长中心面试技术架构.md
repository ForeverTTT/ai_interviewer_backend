## 文档状态

- 状态：第一至第四阶段已实现（数据库迁移待按部署流程执行）
- 最后同步：2026-08-27
- 对应分支：`feature/offer-growth-center-phase-1`
- 前端产品方案：[成长中心改版方案](../../前端/产品与规划/成长中心改版方案.md)
- 关联后端文档：[持久化面试会话方案](../设计方案/持久化面试会话方案.md)、[面试流程技术架构](面试流程技术架构.md)
- 文档定位：记录成长中心与面试 Session、报告、有效训练、Offer 冲刺任务和提醒之间的技术边界与实现约束

## 1. 目标与边界

成长中心不是新的面试状态存储，而是现有面试事实数据的行动化读模型。它需要让用户快速回答三个问题：

1. 最近一次面试产生了什么结果；
2. 当前是否有一场可以继续的练习；
3. 下一步应该打开报告还是恢复原练习。

第一阶段只复用 `interviews` 表及现有面试接口，不新增聚合表、不复制 Session 状态，也不进行跨报告的职场胜算趋势计算。Supabase PostgreSQL 仍是事实来源；成长中心只负责读取、归类和展示。

## 2. 第一阶段交付

第一阶段前端入口仍为 `/dashboard`，用户可见名称统一为“成长中心”。已实现：

- 顶部状态区：职场胜算主卡、练习积累、本周节奏；
- 最新复盘：报告已就绪、报告生成中、无报告、未完成练习和无面试状态；
- 面试复盘记录：整卡可打开，并以高对比度 CTA 区分“查看完整报告”和“继续练习”；
- 状态筛选：全部、报告、待继续；
- 移动端 CTA：按钮默认占满可用宽度，避免卡片点击语义不明确；
- 删除记录：继续使用所有权受控的后端删除接口；
- 中、英、德三套成长中心文案与导航命名。

第一阶段没有修改后端运行时代码。现有接口已经覆盖页面所需字段和原 Session 恢复能力。

## 3. 数据流

```text
GET /api/interviews
  → requireAuth 校验用户
  → interviews.user_id = 当前用户
  → created_at 倒序，最多 50 条
  → 成长中心构造只读页面模型
      ├─ 顶部真实训练统计
      ├─ 最新复盘状态
      └─ 面试复盘记录与 CTA

继续练习
  → /interview/:interviewId
  → GET /api/interviews/:id
  → 校验 user_id 所有权
  → 恢复配置、题目/回答、提示、笔记和服务端计时状态
  → 不调用 POST /api/interviews，不创建新记录

查看完整报告
  → /interview/:interviewId/report
  → GET /api/interviews/:id
  → 读取 report_json / report_markdown / transcript_json
```

## 4. 第一阶段字段映射

| 页面能力 | 事实字段 | 规则 |
|---|---|---|
| 面试身份 | `id`, `user_id` | 所有详情、恢复、报告和删除请求必须同时约束当前用户 |
| 岗位与配置摘要 | `position`, `language`, `duration`, `mode`, `interviewer_type` | 卡片只显示创建该 Session 时保存的配置 |
| Session 状态 | `mode`, `status` | 只有 `mode=practice` 且 `status in (draft, active, paused)` 可恢复；正式模拟不可恢复，离开后使用持久化文本结算报告 |
| 报告生成状态 | `finalize_status`, `finalize_started_at`, `finalize_last_error` | `processing` 显示不可误解的加载态，不跳到空报告 CTA |
| 完整报告 | `report_json`, `report_markdown` | 结构化报告有实际内容或遗留 Markdown 非空时，显示“查看完整报告” |
| 报告摘要 | `report_json.summary[0]` | 仅展示真实报告内容；遗留报告可降级到首个非空 Markdown 行 |
| 报告优势 | `report_json.strengths[0]` | 最新复盘最多显示一条，完整内容仍在报告页 |
| 有效时长 | `accumulated_seconds` | 只累计服务端保存的实际活跃时长；不把配置的 `duration` 当作实际训练时长 |
| 训练日期 | `completed_at`, `updated_at`, `created_at` | 优先级依次降低，用于本周有效天数和展示日期 |
| 恢复上下文 | `graph_state_json`, `transcript_json`, `state_version`, `current_question_id`, `question_index`, `paused_at`, `active_since`, `accumulated_seconds`, `deadline_at` | 由现有持久化 Session 路径恢复，成长中心不得自行拼装或覆盖 |

## 5. 状态到行动的映射

| 条件 | 用户状态 | 主行动 | 目标路由 |
|---|---|---|---|
| 报告存在 | 报告已就绪 | 查看完整报告 | `/interview/:id/report` |
| `mode = practice` 且 `status in (draft, active, paused)` 且无报告 | 未完成/已暂停 | 继续练习 | `/interview/:id` |
| `mode = formal` 且 `status in (draft, active, paused)` 且无报告 | 正式模拟已中断 | 使用持久化 `transcript_json` 触发报告生成，不提供恢复入口 | `/dashboard` |
| `status = finalizing` 或 `finalize_status = processing` | 报告生成中 | 暂无可点击主行动 | 无 |
| `status = completed` 且无报告 | 暂无报告或生成失败 | 查看报告状态 | `/interview/:id/report` |
| 其他终态且无报告 | 已结束 | 不提供误导性恢复入口 | 无 |

判断顺序必须先检查真实报告，再检查可恢复状态，最后检查生成中和其他终态。这样可以兼容历史数据中状态字段与报告落库时间短暂不同步的情况。

## 6. “继续练习”的不变量

成长中心恢复面试时必须满足：

- 路由携带原始 `interviewId`；
- 不调用 `POST /api/interviews`；
- `GET /api/interviews/:id` 必须以 `id + user_id` 校验所有权；
- 练习模式从持久化 question、attempt、hint、note、checkpoint 和计时状态恢复；
- 已暂停练习进入后仍保持暂停，只有显式 resume 动作才能继续累计时长；
- 正式模拟遵循服务端 deadline，不允许通过刷新或重新进入重置时间；
- 已完成且已有报告的记录直接进入报告页，不重新开启 Session。

这些约束由现有 `interviewSessionStore.js`、`interviewSessions.js`、数据库原子函数以及前端 `InterviewPage` / `PracticeInterviewPanel` 共同实现。成长中心只负责提供正确入口。

## 7. 统计口径

### 7.1 练习积累

- 有效练习次数：第一阶段统计已完成 Session，或服务端有效时长达到 8 分钟的 Session；
- 总有效时长：所有记录的正数 `accumulated_seconds` 之和；
- 不使用计划时长 `duration` 补齐缺失的实际时长；
- 不把页面访问、报告浏览或手动签到计入有效训练。

历史记录若没有 `accumulated_seconds` 会被保守地计为 0 分钟。这会低估旧数据，但不会制造虚假投入。后续如需回填，应通过一次明确、可审计的数据迁移完成，不能在前端猜测。

### 7.2 本周节奏与连续天数

- 周起始日为用户本地时间的周一；
- 同一天多场有效练习只记为一个有效训练日；
- 连续天数以自然日去重；当天尚未训练时，允许从昨天向前计算现有连续记录；
- 单纯登录、打开成长中心或浏览报告不计入。

### 7.3 职场胜算

第一阶段只接受报告明确提供的 `overallScore` 或 `overall_score`，且值必须为 `0..100`。当前报告 Schema 尚未标准化该字段，因此默认展示“等待可靠评估”，不从通用个人资料、面试次数或前端占位数据推算分数。

第三阶段引入五维面试准备度后，需要新增版本化评分结构、证据引用和样本不足标记，再替换本占位策略。

## 8. API 与安全边界

第一阶段使用：

- `GET /api/interviews`：读取当前用户最近 50 条记录；
- `GET /api/interviews/:id`：恢复 Session 或读取报告；
- `DELETE /api/interviews/:id`：删除当前用户拥有的记录；
- `POST /api/interview-sessions/:id/resume`：练习页内显式恢复暂停 Session，不由成长中心预调用。

安全要求：

- 每个接口必须经过 `requireAuth`；
- 查询、更新和删除必须同时限制 `user_id = req.user.id`；
- 前端传入的状态、分数、时长均不可作为事实来源；
- 报告摘要只显示已经属于当前用户的报告字段；
- 删除仍属于不可恢复操作，必须保留二次确认。

## 9. 兼容性与已知限制

- `/dashboard` 暂时保留旧 URL，避免已有书签和报告返回链接失效；只改变用户可见名称；
- 现有列表接口使用 `select('*')`，第一阶段开发简单但负载偏大；数据规模增长后应改为专用成长中心 DTO；
- 当前最多读取 50 条记录，长期统计会低估超过窗口的数据；后续聚合接口应在数据库侧计算全量指标；
- 当前报告没有统一基础分数，所以职场胜算主卡不显示伪造数值；
- 邮件提醒只实现受控 outbox：默认关闭，必须配置外部投递 Worker 后才允许用户启用；本服务不直接调用邮件供应商。
- 高级能力当前只有真实标注的规划预览，没有套餐、价格、订阅或支付状态，不能据此限制基础数据访问。

## 10. 第二、第三阶段实现

### 10.1 第二阶段：问答收藏与有效训练事件

- 迁移 `20260826193000_growth_center_phase_2_3.sql` 新增 `interview_question_collections`。卡片统一保存原题、用户回答、反馈快照、职位、语言、面试官类型、来源、私人笔记、标签、置顶和复习状态；`origin_key + user_id` 保证同一原题幂等收藏。
- 旧 `interview_notes` 迁移为练习来源卡片的可选 `personal_note`。保存练习笔记或更新该题答案时，会同步统一卡片；笔记本身不产生有效训练事件。
- 报告页只提供逐题收藏，不提供整份报告收藏或整份报告自由笔记。`POST /api/growth-center/collections` 从用户拥有的 Session 和报告中重新提取权威快照，不信任前端上传的题目、回答或反馈文本。
- `/notes` 是完整收藏库，提供全文搜索、职位/面试官/来源/标签/日期/复习状态筛选、置顶、复习、私人笔记、取消收藏、返回原内容和“再练一次”。
- `POST /api/growth-center/collections/:id/practice` 创建新的练习 Session，并把收藏原题作为首个针对性问题。它不会恢复或改写来源 Session。
- `interview_training_events` 只接受四种有效事实：有效回答、面试完成、系统任务完成、实际训练达到 8 分钟。同一事实由 `dedupe_key` 去重；成长中心按自然日去重，所以同一天最多一次有效打卡。暂停、浏览和单独写笔记均不累计。
- 练习页面在 `pagehide` 时以 keepalive 请求执行服务端 pause，先结算当前活跃秒数再清空 `active_since`；重新进入后保持暂停，避免离开页面的时间被误计为训练。
- `GET /api/growth-center/overview` 只返回最近三条待复习收藏；完整列表由 `GET /api/growth-center/collections` 提供。

### 10.2 第三阶段：报告证据驱动的五维准备度

- 报告 Schema 新增 `careerReadiness.version=1` 和 `nextPracticeTask`。五个固定维度为：技术能力、经历与证据深度、结构化表达、沟通与协作、面试策略与岗位匹配。
- 每个有分数的维度都必须带 `interviewId + questionIndex + excerpt` 证据，以及标题、原因、预计时长和原题组成的可执行动作；无匹配证据时维度状态为 `insufficient`，不从资料完整度或练习次数猜分。
- 聚合最多读取最近 20 份已完成报告，实际计算使用最近 5 份；权重依次考虑新近程度、相似职位和相同面试官类型。
- 单份报告只标记 `initial`，每个维度至少有两份有效评分才计算趋势；因此样本不足不会出现伪趋势。
- 成长中心首屏显示今天唯一的最高价值题，以及最多五个周任务；报告页同样显示下一题。点击后先幂等收藏，再创建针对性练习，形成“报告弱项 → 原题练习 → 新报告证据”的闭环。
- 五维卡片可展开查看证据；报告页和成长中心都能回到证据所属报告。

### 10.3 正式模拟结束语义

- `POST /api/interview-sessions/:id/resume` 对正式模拟显式返回 `409 FORMAL_RESUME_FORBIDDEN`。
- 正式模拟页面在 `pagehide` 和直接路由恢复时，以空 `messages` 调用 finalize；服务端 `selectFinalizeMessages` 自动回退到持久化 `transcript_json`，避免依赖未保存的浏览器内存。
- 成长中心发现未结算的正式模拟时也会幂等触发 finalize，并立即将卡片置为报告生成中。
- 用户在练习或正式模拟中主动点击结束后，前端立即展示“报告正在生成，可在成长中心查看”的提示；请求继续在后台执行，不再阻塞并强制跳转报告页。

### 10.4 第四阶段：Offer 冲刺计划、周报与提醒

- 迁移 `20260827120000_offer_sprint_phase_4.sql` 新增 `growth_offer_plans`、`growth_offer_tasks`、`growth_offer_reminders` 和 `growth_milestones`。所有表以 `user_id` 隔离并启用 RLS；计划可由用户管理，系统任务、提醒和里程碑由服务端生成。登录用户对后三类系统事实只有只读数据库权限，状态变更必须经过带 `user_id` 约束的后端接口。
- 每个用户只有一份当前计划。目标职位必填；JD、下一次面试日期和目标 Offer 日期可选；训练目标只允许 3/5/7 天。用户删除计划时，任务与提醒通过外键级联删除。
- `classifyOfferSprint` 以 UTC 自然日计算剩余天数，按基础期、8–21 天聚焦期、3–7 天临近期、最后 48 小时、面试当天和目标过期六种状态选择任务模板。
- `buildOfferSprintTasks` 把第三阶段的下一题、最近待复习收藏、是否已有正式报告和目标面试官类型合成当周任务。3 天目标最多 3 项，其余最多 5 项；`task_key` 保证同周同来源任务幂等，已完成任务不会被刷新覆盖。
- 每个任务保存原因上下文、预计时长、完成后价值、能力维度以及可选的来源报告题或收藏 ID。聚焦题和收藏题可直接创建新练习；基线/正式模拟进入预填目标的配置页；最后 48 小时的面试清单携带最近三张置顶/待复习题卡。任务可完成或跳过，过期/跳过任务不能再通过状态接口改写。
- `buildWeeklyGrowthReport` 只统计本周真实训练事件、服务端 `accumulated_seconds` 和已完成系统任务。维度趋势必须来自多报告证据；`null` 不会被数值转换成虚假 `0` 趋势。
- 里程碑由服务端根据已有事实幂等生成：首份正式报告、连续 5 天有效训练、单维度提升至少 15 分。
- 面试前 7 天、2 天、当天以及周报提醒会写入 `growth_offer_reminders`。站内提醒默认启用；浏览器通知只在用户交互中请求权限；邮件提醒只有 `GROWTH_REMINDER_EMAIL_OUTBOX_ENABLED=true` 时可选，且仍需外部 Worker 认领待发送记录并更新 `sent/failed`。
- 高级能力返回值只有 `premiumPreview` 和 `existingDataAlwaysAccessible=true`，用于延后展示规划能力；当前没有计费接口，也不能把已有报告、历史、收藏或基础任务置于付费墙后。

## 11. API 总览

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/growth-center/overview` | 五维聚合、最近三条待复习收藏、有效训练节奏 |
| PUT/DELETE | `/api/growth-center/offer-plan` | 保存或删除当前用户的 Offer 冲刺目标 |
| PATCH | `/api/growth-center/offer-plan/tasks/:taskId` | 完成或跳过当前用户的周任务，并幂等记录有效训练事实 |
| PATCH | `/api/growth-center/offer-plan/reminders/:reminderId` | 将当前用户的提醒标记为已读或已关闭 |
| GET | `/api/growth-center/collections` | 收藏库搜索与筛选 |
| POST | `/api/growth-center/collections` | 从练习题或报告逐题生成权威收藏快照 |
| PATCH/DELETE | `/api/growth-center/collections/:id` | 更新私人字段或取消收藏 |
| POST | `/api/growth-center/collections/:id/practice` | 从收藏原题创建新的针对性练习 |
| POST | `/api/growth-center/tasks/:taskId/complete` | 幂等记录系统训练任务完成事实 |

所有接口均先执行 `requireAuth`；收藏查询和变更同时受 `user_id` 条件与 RLS 约束。任务完成接口使用服务端凭证写入，但 `user_id` 只能取认证上下文，不能由请求体指定。

## 12. 后续演进

- 接入邮件供应商时新增独立 Worker，以 service role 读取到期的 email outbox，使用抢占/租约避免重复发送，并回写 `sent/failed`；HTTP 请求链路不承担邮件投递。
- 如果上线付费能力，应新增独立 entitlement/订阅模型和真实价格来源；`premiumPreview` 不能被当作购买资格或扣费依据。
- 任务生成后续可读取更完整的 JD 能力矩阵，但仍必须保留来源证据、任务上限和免费基础闭环。

## 13. 第一至第四阶段验收清单

- 导航、页脚、页面标题和报告返回入口统一使用“成长中心”；
- 有报告记录显示高对比度“查看完整报告”；
- 可恢复记录显示“继续练习”，并进入原 `interviewId`；
- 继续练习不触发新建面试接口；
- 报告生成中、无报告、无面试和筛选无结果均有独立状态；
