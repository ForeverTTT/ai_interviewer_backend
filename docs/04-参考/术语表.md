# 术语表

> 状态：现行 · 最后核对：2026-10-01

按领域分组。"代码中的名称"一列可以直接用来搜索代码。

## 面试

| 术语 | 代码中的名称 | 含义 |
|---|---|---|
| 面试 / 面试会话 | `interviews` 行、`interviewId` | 一场面试的聚合根。所有读取、写入、恢复和实时连接都以它为边界，它同时也是 LangGraph 的 `thread_id` |
| 练习模式 | `mode = 'practice'` | 以学习为目的：不限时，可以暂停、看提示、多次作答、标记掌握或跳过，每次作答立即给出反馈 |
| 正式模式（正式模拟） | `mode = 'formal'` | 以模拟为目的：服务端计时，不能暂停、看提示或重答，结束后统一生成报告 |
| 面试官类型 | `interviewer_type`：`hr` / `technical` / `mixed` | 决定题型、追问方向、RAG 偏好和报告重点。创建后不能修改。策略的唯一来源是 `backend/src/config/interviewerTypes.js` |
| 面试官风格 | `interviewer_style`：`balanced` / `supportive` / `demanding` / `analytical` | 决定表达语气和语音音色，不影响题型 |
| 难度 | `difficulty`：`easy` / `medium` / `hard` / `adaptive` | Adaptive 会根据回答质量动态调整下一题的难度 |
| 当前有效难度 | `current_difficulty` | Adaptive 模式下实际使用的难度（`easy` / `medium` / `hard`） |
| 求职方向 | `role_track`：`school` / `work` | 学校面试或工作面试 |
| 面试语言 | `language`：`English` / `Deutsch` / `Chinese` | AI 提问、TTS 和语音识别使用的语言，与界面语言相互独立 |
| 快照 | `resume_snapshot`、`job_description_snapshot` | 创建面试时复制的简历和 JD，之后修改资料不会影响这场面试 |
| 状态版本 | `state_version` | 乐观锁版本号。写入时版本不匹配就拒绝（409） |
| 幂等键 | `idempotencyKey` | 客户端为每个有副作用的动作生成的唯一键。重试时返回第一次的结果，不会重复执行 |
| Checkpoint | `graph_state_json` | LangGraph 状态的持久化快照，用于恢复面试 |
| 截止时间 | `deadline_at` | 正式面试由服务端决定的结束时间，浏览器倒计时只用于显示 |
| 截止宽限 | `complete_formal_answer_after_deadline` | 正式面试到达截止时间时，如果候选人正在作答，允许答完当前这一题，但不会再出新题 |
| 四级提示 | `nudge` → `structure` → `key_points` → `example` | 练习模式中逐级开放的提示，四级用完后不能再要 |
| 掌握 / 跳过 / 重答 | `master` / `skip` / `retry` | 练习题的状态动作。没有作答过的题不能标记为掌握 |
| 能力矩阵 | `competency_matrix_json` | 从 JD 要求中提取的能力项，与简历证据对应；每次作答都按能力项打分 |
| 报告定稿 | `finalize`、`finalize_status` | 生成最终报告的过程。状态有 `not_started` / `processing` / `failed` / `completed`，同一时间只有一个请求能抢到锁 |
| 兼容 transcript | `transcript_json` | 旧版客户端和报告使用的对话记录格式，与新表同步维护 |
| RAG | `retrieveExperienceContext` | 练习出题时从面经库检索相关面经作为参考 |

## 语音

| 术语 | 代码中的名称 | 含义 |
|---|---|---|
| Gemini Live | `/api/chat/live`、`useGeminiLiveInterview` | 基于 WebSocket 的实时语音对话 |
| 输出闸门 | 见[面试流程 · Live 输出闸门](../03-技术与架构/模拟面试/面试流程.md#92-live-输出闸门) | 练习模式录音时，Live 只负责转写，不会自动给出语音回应 |
| TTS 降级链 | `useStreamingTTS` | 流式 TTS → 完整 TTS → 浏览器 SpeechSynthesis → 静默。只用于兼容通道，当前面试的声音由 Gemini Live 生成 |
| 数字人 | `AvatarProvider` | 口型同步的面试官形象，目前是未接入的脚手架 |

## 成长中心

| 术语 | 代码中的名称 | 含义 |
|---|---|---|
| 成长中心 | `/dashboard`、`/api/growth-center` | 在导航中曾经叫"面试历史"或"仪表盘" |
| 职场胜算 / 准备度 | readiness，五个维度 | 只依据正式面试报告评估的五维准备度：技术、经历证据、结构表达、沟通协作、策略匹配 |
| 有效训练 | `interview_training_events` | 可以计入训练节奏的事件，口径见[成长中心](../03-技术与架构/成长中心.md#32-统计口径) |
| Offer 冲刺计划 | `growth_offer_plans` | 用户设定的目标岗位和日期，系统据此生成每周任务和提醒 |
| 冲刺阶段 | `stage`：`foundation` / `focused` / `imminent` / `final48` / `interview_day` / `renew` | 根据距离面试的天数划分（分界点为 21、7、2、0 天） |
| 题目收藏 | `interview_question_collections`、`/notes` | 从练习或报告中收藏的题目、回答与反馈，界面上叫"题目收藏"或"面试笔记" |

## 账户

| 术语 | 代码中的名称 | 含义 |
|---|---|---|
| 能量值 | `tokens` | 界面上的计费单位。注意不要和 LLM 的 token 或 access token 混淆 |
| 打卡 / 连续天数 | `daily_streak`、`/api/profile/check-in` | 旧版的每日打卡，与成长中心的有效训练天数是两套独立的统计 |
| 等级 | `game-stats` 中的 `level` | 1–10 级，实时计算，不单独存储 |

## 基础设施

| 术语 | 含义 |
|---|---|
| Service Role | Supabase 的管理员密钥，可以绕过 RLS，只能放在后端 |
| Anon Key | Supabase 的公开密钥，会编译进前端代码，安全性由 RLS 保证 |
| RLS | Row Level Security，PostgreSQL 的行级权限控制 |
| WIF | Workload Identity Federation，GitHub Actions 通过 OIDC 免密登录 Google Cloud |
| Revision | Cloud Run 的一个部署版本，回滚时切换的就是 revision |
| `live` 频道 | Firebase Hosting 的正式站点频道；PR 会部署到独立的预览频道 |
