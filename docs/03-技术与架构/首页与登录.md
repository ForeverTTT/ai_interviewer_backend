# 首页与登录

> 状态：现行 · 最后核对：2026-10-01 · 产品说明：[首页与登录](../01-产品/功能说明/首页与登录.md)
> 代码：`frontend/src/pages/LandingPage.jsx`、`frontend/src/components/landing/`、`frontend/src/pages/LoginPage.jsx`、`frontend/src/pages/AuthCallbackPage.jsx`、`frontend/src/components/ProtectedRoute.jsx`、`frontend/src/hooks/useAuth.js`、`frontend/src/lib/authenticatedFetch.js`、`backend/src/middleware/auth.js`

## 1. 落地页

- 路由 `/` 使用 `Layout(atmosphere=false)`：顶栏 + 页脚，没有背景大气层，因为落地页自带主视觉。
- 区块顺序：`HarborHero` → `OfferLogosMarquee` → `HowItWorksShowcase` → `AdvantagesShowcase` → `TechnologyShowcase` → `TestimonialsMarquee` → `ClosingCta`。
- 主按钮目标 `ctaLink`：已登录为 `/setup`，未登录为 `/login`。
- 收尾区的 3D 拱廊（`ArchCorridor3D`）按需动态加载 `three`，离开视口就停止渲染，卸载时释放 GPU 资源；不支持 WebGL 或用户开启了"减少动态效果"时，显示静态兜底。

## 2. 登录与会话

```text
LoginPage ──signInWithOAuth──► Supabase Auth（Google / LinkedIn OIDC）
                                     │
                    /auth/callback ◄─┘  AuthCallbackPage：exchangeCodeForSession
                                     │
                       Supabase Session（JWT，存在 localStorage，自动续期）
```

- 支持 `google` 和 `linkedin_oidc` 两种方式，回调地址为 `<origin>/auth/callback`。新的部署域名需要加入 Supabase Auth 的 Redirect URL。
- 本地开发可以设置 `VITE_LOCAL_SUPABASE=true`，改为邮箱密码登录，见[本地开发](../02-开发指南/本地开发.md#本地登录)。
- 授权码只能兑换一次。回调页会复用正在进行的兑换请求，以兼容 React StrictMode 在开发环境中重复执行 Effect。回调出错时把错误留在页面上，不会自动清除会话。
- 新用户注册时，数据库触发器 `on_auth_user_created` 会自动创建 `profiles` 行（初始能量值 1000）。后端的 `ensureProfileRow` 也会在缺少这一行时补建。

## 3. 登录后跳转

| 入口 | 跳转 |
|---|---|
| `ProtectedRoute` 拦截未登录用户 | `<Navigate to="/login" state={{ from: location }}>` |
| `LoginPage` 检测到已登录 | 跳回 `state.from.pathname`，没有时进入 `/setup` |
| `AuthCallbackPage` 兑换成功 | 固定进入 `/setup` |

OAuth 会离开当前页面，`state.from` 在回调后已经丢失，所以第三方登录后总是进入 `/setup`。这是一个已知问题，见[问题与想法](../问题与想法.md)。

## 4. 路由守卫

`ProtectedRoute` 订阅 `supabase.auth.onAuthStateChange`。会话加载期间显示品牌加载页；没有会话时重定向到登录页。面经库 `/experiences` 不包这一层，而是用 `AdaptiveLayout` 根据登录状态切换布局，见[前端架构 · 路由系统](通用机制/前端架构README.md#4-路由系统)。

## 5. 请求鉴权

后端的鉴权（`requireAuth`）和前端遇到 401 时的处理（`authenticatedFetch`）对所有模块通用，见[账户与计费 · 后端鉴权](通用机制/账户与计费.md#1-后端鉴权)。
