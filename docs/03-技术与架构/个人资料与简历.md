# 个人资料与简历

> 状态：现行 · 最后核对：2026-10-01 · 产品说明：[个人资料与简历](../01-产品/功能说明/个人资料与简历.md)
> 代码：`backend/src/routes/profile.js`、`frontend/src/pages/ProfilePage.jsx`、`frontend/src/lib/cvProfileDefaults.js`

本文说明默认简历的存储、PDF 解析、结构化提取和简历诊断。面试配置、简历优化都通过同一组接口读取和保存简历。扣费规则见[账户与计费](通用机制/账户与计费.md#21-消耗)。

## 1. 数据存放

都在 `profiles` 表中，一个用户一行：

| 字段 | 内容 |
|---|---|
| `resume_text` | 简历纯文本，是所有 AI 功能的输入来源 |
| `resume_notes` | 用户的补充说明 |
| `profile_json.cvProfile` | 结构化简历（个人信息、工作经历、教育、项目、技能等），默认结构见 `frontend/src/lib/cvProfileDefaults.js` |
| `profile_json.coach_cache` | 简历诊断的多语言翻译缓存 |
| `resume_coach` | 最近一次简历诊断结果 |
| `resume_updated_at` | 简历最后更新时间 |
| `job_search_status` | 求职状态（默认 `seeking`；`hired` 时等级直接升到 10） |
| `avatar_id` | 头像：预设头像 ID，或 `avatars` 存储桶中的公开 URL |

创建面试时，简历会以快照形式复制到 `interviews.resume_snapshot`，之后修改简历不会影响历史面试。

## 2. 处理流程

```text
PDF ──parse-pdf──► 纯文本 ──（用户确认）──PUT /profile──► resume_text
                                                         │
                         ┌───────────────────────────────┤
                         ▼                               ▼
          extract-cv（50）→ cvProfile           resume-coach（200）→ 诊断
          前端合并后经 PUT /profile 保存         保存到 resume_coach
```

### 2.1 PDF 解析 `POST /api/profile/resume/parse-pdf`

- 请求体是 `{ pdfBase64 }`。PDF 解码后最大 12 MB，所以这个路由的 JSON 大小上限单独放宽到 17 MB。
- 校验 `%PDF-` 文件头，用 `pdf-parse-fork` 提取文本。
- 错误码：`PDF_MISSING`、`PDF_INVALID`、`PDF_TOO_LARGE`（413）、`PDF_NO_TEXT`（422，扫描件没有可选文本）、`PDF_PASSWORD_PROTECTED`、`PDF_UNREADABLE`。
- 提取的文本少于 80 个字符时，返回 `warning` 提示可能是扫描件。
- 不扣费，也不自动保存，由前端让用户确认后再调用 `PUT /api/profile`。

### 2.2 结构化提取 `POST /api/profile/extract-cv`

- 输入：请求中的 `resumeText`（至少 80 个字符），否则使用已保存的 `resume_text`；截取前 48,000 个字符。
- Gemini 以 JSON 格式返回结构化字段（temperature 0.2）；JSON 解析失败返回 502。
- 后端**不保存**结果，只返回 `cvProfile`；前端用 `mergeCvProfileFromApi` 合并后再经 `PUT /api/profile` 保存。

### 2.3 简历诊断 `POST /api/profile/resume-coach`

- 输入：`targetRole`（可选）、`resumeText`（可选，规则同上）、`coachUiLanguage`（界面语言）。
- 模型输出结构：

| 字段 | 内容 |
|---|---|
| `overallEvaluation` | 整体评价 |
| `scores` | `overall`、`clarity`、`impact`、`structure`、`ats`，都是 1–10 的整数 |
| `macroInsights` | 3–5 条文档层面的洞察 |
| `highlights` | 亮点 |
| `priorityImprovements` | 2–4 条优先改进项，可以附改写示例 |
| `moduleDeepDives` | 逐模块 / 逐条的诊断，带 `before` / `after` 对比 |
| `positioning` | 定位建议 |
| `actionChecklist` | 按优先级排列的行动清单 |

- 界面上显示的"专业度"不是模型输出的，而是由前端用 `(structure + clarity) / 2` 计算得出。
- **语言处理**：模型先用英文写叙述性内容，改写示例（`rewriteExample`、`after`）保持简历原文的语言；然后后端把叙述性字段翻译成界面语言。
- 结果写入 `resume_coach`，同时清空 `coach_cache`。保存失败时返回 `persisted: false`，**并且不扣费**。

### 2.4 诊断翻译 `POST /api/profile/resume-coach/translate`

切换界面语言时调用，不重新分析。按目标语言（`zh-CN` / `en` / `de`）缓存在 `profile_json.coach_cache` 中。如果缓存的 `generatedAt` 与当前报告一致，就直接返回缓存。不扣费。

> 翻译调用的是非官方接口 `translate.googleapis.com/translate_a/single?client=gtx`，没有 SLA；失败时返回原文。

## 3. 头像

- 预设头像是 5 个 DiceBear identicon 的 URL，直接存进 `avatar_id`。
- 自定义头像由浏览器直接上传到 Supabase Storage 的 `avatars` 存储桶（路径 `user_avatars/<userId>-<时间戳>.<扩展名>`，前端限制 2 MB），然后把公开 URL 存进 `avatar_id`。

## 4. 等级与打卡（后端保留，界面未接入）

> 当前前端没有调用 `game-stats` 和 `check-in`，成长中心改为使用 `/api/growth-center/overview`。这两个接口目前只保留在后端。

`GET /api/profile/game-stats` 根据当前数据实时计算以下指标，不单独存储：

- **四维雷达**（每项 0–10 分）：简历完整度、实战经验（已完成面试数）、语言能力（德语面试权重更高）、软技能；
- **等级**（1–10 级）：按完成面试数、简历分、已掌握题数、连续打卡天数、雷达平均分等条件依次判断，`job_search_status = 'hired'` 时直接为 10 级；
- **连续打卡**：读取 `daily_streak` 和 `last_activity_at`，如果最后一次打卡早于昨天，就显示为 0。

注意：这里的打卡（`profiles.daily_streak`）和成长中心的"有效训练天数"（`interview_training_events`）是**两套独立的统计**，后者的口径见[成长中心](成长中心.md#32-统计口径)。


## 5. 已知限制

- AI 结果的 JSON 解析依赖 `stripJsonFence`，模型偶尔返回不合法的 JSON 时会报 502，需要用户重试。
- 诊断翻译依赖非官方的 Google 翻译接口。
