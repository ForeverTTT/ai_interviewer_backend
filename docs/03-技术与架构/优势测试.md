# 优势测试

> 状态：现行（解读文案为占位内容） · 最后核对：2026-10-01 · 产品说明：[优势测试](../01-产品/功能说明/优势测试.md)
> 代码：`backend/src/routes/gallup.js`、`backend/scripts/seedGallup.js`、`backend/scripts/seedGallupContent.js`、`frontend/src/pages/GallupTestPage.jsx`、`frontend/src/components/GallupReport.jsx`、`frontend/src/components/GallupRadar.jsx`

## 1. 数据

| 表 | 内容 | 写入方 |
|---|---|---|
| `gallup_questions` | 20 道题，带 `index_number`、`category`（四大领域之一）和中英德三语题干 | `supabase/seed.sql` 或 `scripts/seedGallup.js` |
| `gallup_analysis_content` | 按 `领域 × 档位(high/medium/low) × 语言` 预先写好的解读，每份 5 个维度 | `scripts/seedGallupContent.js`（目前是占位文案） |
| `gallup_responses` | 每个用户一行：`answers`、`results`、`status` | 后端 |

四大领域的 key：`executing`（执行力）、`influencing`（影响力）、`relationship`（关系建立）、`strategic`（战略思维）。

## 2. 流程

```text
GET /questions ──► 用户逐题作答（1–5 分）──► POST /save（自动保存进度，不扣费）
                                              │
                    前端计算每个领域的得分 ◄──┘ 全部答完后
                                              │
                    POST /analyze（100）──► 后端按档位查询解读 ──► 写入 gallup_responses
```

- **计分在前端**：每个领域的得分 = 该领域各题得分之和 ÷（题数 × 5）× 100，未作答的题按 3 分计算。
- **分档在后端**：得分 ≥ 75 为 `high`，≥ 40 为 `medium`，否则为 `low`。
- **解读不是 AI 生成的**：`/analyze` 从 `gallup_analysis_content` 中查出对应档位的三语解读，组装成 `results = { scores, analysis }` 后保存。如果解读表还没有填充，`dimensions` 就是空数组。
- 读取旧结果时（`GET /results`），如果发现缺少 `translations` 字段，会自动从解读表补全。

## 3. 已知限制

- 分数由客户端提交，后端不重新计算，因此不能作为可信的评估结果。
- `/analyze` 依赖请求中的 `results`，没有做请求体校验。
- 解读文案目前是脚本生成的占位内容。

- 页面上有"重新开始 / 重新测试"的文案，但没有对应按钮，用户无法重测；后端 `/save` 可以覆盖结果，只是前端没有入口。
