# 面经库

> 状态：现行 · 最后核对：2026-10-01 · 产品说明：[面经库](../01-产品/功能说明/面经库.md)
> 代码：`backend/src/routes/experiences.js`、`backend/src/lib/interviewLearning.js`（RAG 检索）、`frontend/src/pages/ExperiencesPage.jsx`

## 1. 数据

表 `interview_experiences`：`type`、`company`、`location`、`position`、`department`、`date`（`YYYY-MM`）、`language`、`rounds`（每轮的形式、时长、题目）、`result`、`salary`、`reflection`、`publisher`（发布者的名字或邮箱前缀）、`user_id`。

RLS：任何人（包括未登录用户）都可以读取；只有作者本人可以新增和删除。

## 2. 接口行为

| 接口 | 鉴权 | 行为 |
|---|---|---|
| `GET /api/experiences` | 公开 | 返回全部面经，按时间倒序（**没有分页**） |
| `GET /api/experiences/mine` | 需要登录 | 返回当前用户发布的面经 |
| `POST /api/experiences` | 需要登录 | 用 zod 校验字段；每个用户每个 UTC 自然日最多 1 篇；成功后奖励 200 能量值 |
| `DELETE /api/experiences/:id` | 需要登录 | 只能删除自己的面经；扣回 200 能量值 |

这个路由没有使用 `requireAuth` 中间件，而是在处理函数里用 `supabaseForUser(token).auth.getUser()` 自行验证 token。

## 3. 前端

`/experiences` 使用 `AdaptiveLayout`：已登录时显示在 `AppShell` 中，未登录时显示官网布局。页面提供统计卡片、类型筛选（全部 / 实习与学生工 / 学校面试）、全文搜索（企业、岗位、题目、感想），`?mine=true` 只显示自己发布的面经。筛选和搜索都在前端完成。

## 4. 用作面试题目来源（RAG）

练习模式出题时，`lib/interviewLearning.js` 的 `retrieveExperienceContext` 读取最近 100 篇面经，按岗位、JD 关键词匹配和面试官类型排序，取前 4 篇作为出题参考，并在题目的 `source_metadata` 中记录来源。详见[面试流程 · 能力矩阵与 RAG](模拟面试/面试流程.md#103-能力矩阵与-rag)。

因此，用户分享的面经会直接影响其他用户的练习题目。

> `backend/data/knowledge_base/interview_experiences.json` 目前没有被任何代码读取。RAG 使用的是数据库中的 `interview_experiences` 表。

## 5. 已知限制

- 列表接口没有分页，面经增多后响应会越来越大。
- 面经内容没有审核，会直接进入 RAG。
- 删除面经时扣回的奖励使用 `deduct_user_tokens`，余额最低扣到 0。
