## 通信方式

| 通道 | 路径 | 用途 |
|---|---|---|
| REST JSON | `/api/*` | 绝大多数业务接口 |
| SSE | `POST /api/chat/message` | LangGraph 文本面试的流式回复。**兼容通道，当前前端未启用** |
| 流式音频 | `POST /api/chat/tts-stream` | 返回 PCM 音频流，边收边播。**兼容通道，当前前端未启用** |
| WebSocket | `/api/chat/live` | Gemini Live 实时语音面试。**当前所有面试都走这条通道**，面试官的声音由 Live 直接生成 |
| 浏览器直连 Supabase | Supabase JS SDK | 登录和会话管理；上传头像到 `avatars` 存储桶；后端请求失败时直接读取 `profiles.tokens` 作为余额兜底。其他业务数据都经过后端读写 |

完整的接口清单见 [API 参考](../04-参考/API.md)。

## 核心原则

1. **PostgreSQL 是业务状态的唯一事实来源**。Cloud Run 实例可以随时扩缩容，进程内存只保存临时连接状态。
2. **`interviewId` 是面试的隔离边界**。读取、写入、恢复和实时连接都以它为准，它同时也是 LangGraph 的 `thread_id`。
3. **有副作用的操作必须幂等**，并通过 `state_version` 乐观锁防止并发覆盖。
4. **服务端权威**：正式面试的截止时间、分数和能量值余额都由服务端决定，前端只负责显示。
5. **密钥只在服务端**：Service Role Key 和 Gemini Key 不能进入任何 `VITE_*` 变量。

## 横切机制

| 机制 | 实现位置 | 说明 |
|---|---|---|
| 安全响应头 | `backend/src/index.js` → Helmet | 包括 CSP、HSTS 等 |
| CORS | `backend/src/index.js` | 允许 `FRONTEND_URL` 和本地常用端口，并暴露 `X-Request-Id` 响应头 |
| 限流 | `express-rate-limit` | 所有 `/api/*`（`/api/ux-events` 除外）：每 IP 每 15 分钟 1000 次；`/api/chat` 和 `/api/ai-assistant` 额外限制为每小时 500 次；`/api/ux-events` 单独限制为每 IP 每分钟 120 次 |
| 请求体大小 | `express.json` | 默认 10 MB；`/api/profile/resume/parse-pdf` 放宽到 17 MB（Base64 编码的 12 MB PDF） |
| Request ID | `lib/observability.js` | 每个请求都有 ID，记录在结构化日志和 `interview_events` 中 |
| 结构化日志 | `logStructured` | 自动脱敏 API Key、JWT 和 Bearer token。产品埋点也写成 `analytics.*` 结构化日志，见[埋点与数据分析](通用机制/埋点与数据分析.md) |
| 健康检查 | `GET /api/health` | 返回 `commit`、`revision`、`deployedAt`，用来确认部署的是哪个版本 |
