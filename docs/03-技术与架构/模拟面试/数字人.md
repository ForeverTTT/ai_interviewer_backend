# 数字人

> 状态：**脚手架，未接入**（没有被任何页面引用，生产环境中不生效） · 最后核对：2026-10-01 · 产品说明：[模拟面试](../../01-产品/功能说明/模拟面试.md)
> 代码：`frontend/src/avatar/`

面试房间目前显示的是一张静态面试官图片（`public/images/interviewer-hr.png`）。`avatar/` 目录为将来的口型同步数字人搭好了抽象层，但还没有接入 `ChatInterface` 或任何页面。

## 1. 设计目标

- **与语音模型解耦**：数字人只接收音频块，不关心音频来自 Gemini Live 还是 TTS。
- **可以更换供应商**：MuseTalk / LiveTalking、Tavus、Simli、火山引擎等都实现同一个接口。
- **数字人故障不影响面试**：任何环节出错，都回退到静态头像，面试照常进行。

## 2. 模块

| 文件 | 作用 |
|---|---|
| `AvatarProvider.js` | 抽象基类，定义生命周期和状态机 |
| `NullAvatarProvider.js` | 静态头像实现（默认）：不渲染，只维护一个"正在说话"标志（250 ms 防抖） |
| `MuseTalkAvatarProvider.js` | MuseTalk / LiveTalking 适配器，**占位实现**：联网部分都是 TODO，`checkAvailability()` 始终返回不可用 |
| `createAvatarProvider.js` | 供应商注册表。未知名称或不可用的供应商会回退到 `NullAvatarProvider` |
| `AudioRouter.js` | 把一路音频分发给多个接收端：本地播放是主接收端，永远最先执行；数字人是次要接收端，连续出错 5 次后自动断开 |
| `interviewerRegistry.js` | 面试官名册：元数据从后端获取，图片从 `src/assets/interviewers/<id>/` 获取 |
| `validation.js` | 前端可以检查的就绪条件（缺少头像、缺少缩略图、音色配置不合法、供应商不可用等） |

### 生命周期

```text
initialize(config) → startSession() → pushAudio(chunk)… → interrupt()（被打断时）→ stopSession() → destroy()
状态：idle → initializing → ready → active → stopped → destroyed（任何阶段都可能进入 error）
```

所有方法都要求幂等，调用顺序错乱时也不能抛出异常。

### 规划中的 MuseTalk 架构

```text
浏览器 ──PCM 16k──► LiveTalking（自部署的 Python 服务）──WebRTC 视频──► <video>
浏览器音频仍然由本地 Web Audio 播放，与视频按时间戳对齐
```
