> 状态：现行（代码已实现；BigQuery 导出需按[数据分析运维](../../05-运维/数据分析.md)配置） · 最后核对：2026-10-04 · 产品说明：[通用规则 · 数据与隐私](../../01-产品/通用规则.md#6-数据与隐私)
> 代码：`backend/src/lib/analytics.js`、`backend/src/routes/uxEvents.js`、`backend/src/routes/feedback.js`、`frontend/src/lib/analytics.js`、`frontend/src/lib/autocapture.js`、`frontend/src/components/FeedbackPrompt.jsx`、`frontend/src/components/CookieBanner.jsx`

产品分析用的埋点。设计取舍见[数据埋点与分析方案](../../06-决策与方案/进行中/数据埋点与分析方案.md)；GCP 配置、指标和查询见[数据分析运维](../../05-运维/数据分析.md)。面试排障用的 `interview_events` 是另一套机制，见[面试流程](../模拟面试/面试流程.md)。

## 1. 架构

```
浏览器（已同意 Cookie）                      后端业务代码
track() / 自动采集                           trackServerEvent()
   │ POST /api/ux-events（批量）                  │
   └──────────────► backend/src/lib/analytics.js ◄┘
                    • 事件白名单 + props 白名单
                    • logStructured('info', 'analytics.<name>')
                                   │
                    Cloud Logging（Cloud Run 自动收集）
                                   │ Log Sink
                    BigQuery 数据集 analytics（europe-west1）

用户主动反馈：FeedbackPrompt → POST /api/feedback → trackServerEvent('feedback_submitted')
```

所有事件最终都是一行 `analytics.*` 结构化日志，没有数据库表，也不经过第三方。

## 2. 事件格式

```json
{
  "severity": "INFO",
  "event": "analytics.interview_completed",
  "timestamp": "日志写入时间",
  "schemaVersion": 1,
  "source": "server 或 client",
  "userId": "uuid 或 null",
  "anonymousId": "前端匿名 ID 或 null",
  "sessionId": "前端会话 ID 或 null",
  "requestId": "…",
  "interviewId": "uuid 或 null",
  "occurredAt": "事件发生时间",
  "pagePath": "/interview/:id",
  "referrerHost": "www.linkedin.com",
  "utmSource": "…", "utmMedium": "…", "utmCampaign": "…",
  "uiLocale": "zh",
  "appVersion": "commit SHA / preview-<SHA> / dev",
  "deviceType": "desktop / mobile / tablet",
  "browser": "chrome", "os": "windows",
  "service": "Cloud Run 服务名，本地为 local",
  "revision": "Cloud Run revision",
  "props": "{\"mode\":\"formal\",\"messageCount\":18}"
}
```

- **顶层字段固定**，没有值时写 `null`。服务端事件没有前端上下文字段（pagePath、utm 等都是 `null`）。
- **`props` 是 JSON 字符串**：BigQuery Log Sink 按第一次见到的类型推断列类型，不同事件的同名字段类型不一致会导致写入失败。查询时用 `JSON_VALUE(props, '$.mode')`。
- **`schemaVersion`**：某个事件的字段含义变化时加 1（`ANALYTICS_SCHEMA_VERSION`）。
- **命名**：事件名 `对象_动作过去式`（snake_case）；props 字段 camelCase；耗时以 `Ms` / `Sec` 结尾。

### 数据红线

props 中只允许枚举、数字、布尔值、长度和界面标签。以下内容不得出现在埋点中：简历 / JD / 回答 / 报告 / 面经的正文，邮箱、姓名、电话、头像 URL，IP 和原始 User-Agent，token 和密钥，URL 的 query string（UTM 除外）。

由后端强制执行：`backend/src/lib/analytics.js` 为每个事件定义 zod schema，未登记的事件丢弃，未登记的 props 字段自动去掉，每个文本字段有长度上限，props 超过 2 KB 的事件丢弃。被拒绝的事件写一条 `analytics_event_rejected` 警告日志（不导出到 BigQuery）。埋点出错一律吞掉，不影响业务。

**只有用户在 Cookie 横幅点"全部接受"后才采集。** 白名单在 `backend/src/lib/analytics.js` 的 `CLIENT_EVENTS`。

### 4.3 采集与发送

| 项目 | 规则 |
|---|---|
| 同意 | `cookie-consent` = `accepted` 才采集。之前不生成 ID、不写存储、不发请求；拒绝时清空队列并删除 ID |
| 匿名 ID | `fl_anon_id`，localStorage |
| 会话 | `fl_session`，localStorage，多标签页共享，30 分钟没有事件后换新 |
| 来源 | UTM 参数和外部 referrer 域名，在会话第一次进入时记录（sessionStorage `fl_attribution`） |
| 身份 | 已登录时带上本地 Supabase 会话的 token，后端据此得到 userId；不主动刷新 token，过期时按匿名处理 |
| 发送 | 每 5 秒或攒满 10 条发一次，每批最多 20 条；标签页隐藏或关闭时用 `fetch(..., { keepalive: true })` 发出（`sendBeacon` 不能带 `Authorization`）；每次页面加载最多 2000 条 |
| 停留时长 | 只累计标签页可见、且距上次操作不超过 30 秒的时间；隐藏后回来继续计时，不重复记 `page_viewed`，所以一次浏览可能有多段 `page_left` |
| 路径 | UUID 和长数字段归一化为 `:id` / `:n` |
| API 监控 | 包装一次 `window.fetch`，只观察发往本站后端 `/api/` 的请求（不含 `/api/ux-events`），不改变请求和响应 |
| 接口命名 | `/api/ux-events` 避开 `analytics`、`track`、`collect` 等会被广告拦截插件屏蔽的词 |
| 版本 | `VITE_APP_VERSION`：正式部署为 commit SHA，PR 预览为 `preview-<SHA>`，本地为 `dev` |

### 4.4 隐私保护

- **不读取输入内容**：文本框只记长度；下拉框和单选框记选项值（界面选项）；邮箱、密码、电话输入框连选项值也不记；复选框和单选框的点击不记标签。
- **标签**：优先用 `aria-label` / `title`；用可见文字时，超过 40 个字符视为内容，只记点击不记文字。所有文本遮蔽邮箱和 4 位以上数字，截断到 60 个字符。
- **遮蔽区域**（`data-track-mask`）：面试对话记录（`ChatInterface.jsx`）、报告逐句复盘（`InterviewReportPage.jsx`）、成长中心收藏卡片（`DashboardPage.jsx`）、收藏题库列表（`NotesPage.jsx`）、配置页 JD 历史（`SetupPage.jsx`）。**新增展示用户内容的可点击列表时必须加上。**
- React `useId()` 生成的 ID（含 `:`）不作为 `trackId`、字段名或区域名。

### 4.5 标记约定

| 属性 | 作用 |
|---|---|
| `data-track="cta-hero-start"` | 稳定名字，不随界面语言和文案变化 |
| `data-track-section="pricing"` | 区域名，区域内所有事件的 `section` 都是这个值 |
| `data-track-mask` | 区域内的文字永不采集 |
| `data-track-ignore` | 区域内完全不采集 |

## 5. 后端接收（`POST /api/ux-events`）

接口说明见 [API 参考](../../04-参考/API.md#产品埋点-apiux-events)。

- **可选鉴权**：有 token 就用 Supabase 校验得到 userId（按 token 哈希缓存 5 分钟）；没有或无效按匿名处理。不信任请求体里的 userId。
- **校验**：每批 1–20 条，逐条按 `CLIENT_EVENTS` 校验，不合格的单条丢弃并写一条 `ux_events_rejected` 警告日志。
- **补充字段**：由 User-Agent 粗分 deviceType、browser、os，原始 UA 和 IP 不记录；客户端时间与服务器相差超过 24 小时时用服务器时间。
- **限流**：单独的限流器，每 IP 每分钟 120 次，挂在全局限流器之前，不占用户正常调用接口的额度。

## 6. 用户反馈

`frontend/src/components/FeedbackPrompt.jsx`，放在 AI 结果下方：

| 位置 | feature | 结果标识 |
|---|---|---|
| 面试报告页底部（`InterviewReportPage.jsx`） | `interview_report` | 面试 ID（同时带上 interviewId） |
| 简历优化结果（`ResumeTailorPage.jsx`） | `resume_tailor` | 每次生成成功的时间 |
| 求职信结果（`ResumeTailorPage.jsx`） | `cover_letter` | 每次生成成功的时间 |
| 简历诊断结果（`ProfilePage.jsx` 的 `CoachReport`） | `resume_diagnose` | 诊断的 `generatedAt` |
| 优势测试报告（`GallupReport.jsx`） | `gallup` | 各领域得分 |

- 点 👍 / 👎 立即提交；之后可多选预设原因再提交一次，或跳过。两次用同一个 `feedbackId`，分析时取最后一条。
- 原因代码（`FEEDBACK_REASONS`，前后端各一份，需保持一致）：👍 `accurate`、`actionable`、`clear`、`saves_time`；👎 `inaccurate`、`too_generic`、`hard_to_understand`、`missing_info`、`too_slow`。后端只接受与 rating 对应的代码，**没有自由文本**。
- 反馈状态记在 localStorage `fl_feedback:<feature>:<结果标识>`，同一结果不重复询问。
- 走需要登录的 `POST /api/feedback`，记为服务端事件，不依赖 Cookie 同意。
- 反馈**不关联也不保存**用户的简历、JD 或生成结果；简历优化和求职信的结果本身也不在后端保存。

## 7. 新增或修改埋点

1. 先明确要回答的问题，再决定事件。
2. 在 `backend/src/lib/analytics.js` 的 `SERVER_EVENTS` 或 `CLIENT_EVENTS` 中添加 schema。未登记的事件会被丢弃。
3. 服务端调用 `trackServerEvent(req, name, { props })`；前端调用 `track(name, props)`（`frontend/src/lib/analytics.js`）。
4. 检查 props 是否触碰数据红线；新的可点击内容列表加 `data-track-mask`。
5. 修改已有事件的字段含义时，`ANALYTICS_SCHEMA_VERSION` 加 1。
6. 更新本文的事件字典；合并后在 BigQuery 确认数据正常落库。

## 9. 已知限制

| 项目 | 说明 | 应对 |
|---|---|---|
| 客户端数据不完整 | 未同意 Cookie、广告拦截插件都会导致缺失 | 计数以服务端事件为准；客户端数据看比例和趋势 |
| 不能直接 JOIN 业务表 | BigQuery 与 Supabase 是两个系统 | 把维度写进事件；需要时做定时同步 |
| 日志写入尽力而为 | 实例被强制终止时可能丢少量日志 | 分析可以接受；计费以 Supabase 为准 |
| 标签随语言变化 | 同一按钮在中、英、德界面下 label 不同 | 按 `pagePath + section` 分组；关键按钮加 `data-track` |
| 新页面的内容泄露风险 | 展示用户内容的短按钮（不足 40 字）可能被记下文字 | 加 `data-track-mask`；代码评审时检查 |
| INP 是近似值 | 取本次加载最慢的一次交互 | 看趋势；需要精确值时改用 `web-vitals` 库 |
