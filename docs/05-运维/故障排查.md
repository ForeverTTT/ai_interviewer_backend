# 故障排查

> 状态：现行 · 最后核对：2026-10-01

先根据现象找到对应的小节；如果某个领域文档已经有详细说明，这里只写结论并给出链接。

## 先看哪里

| 信息 | 位置 |
|---|---|
| 线上运行的是哪个版本 | `GET /api/health` 中的 `commit`、`revision` |
| 一次请求的完整链路 | 响应头 `X-Request-Id`，用它在 Cloud Run 日志中搜索 |
| 某场面试发生了什么 | `interview_events` 表（按 `interview_id` 查询），包含报告生成的各个阶段和错误码 |
| 部署是否成功 | GitHub Actions 中对应工作流的日志 |

## 本地开发

| 现象 | 原因与处理 |
|---|---|
| 前端请求打到了线上后端 | `frontend/.env` 中设置了 `VITE_API_URL`，它的优先级高于 `VITE_BACKEND_URL`。删掉它后重启 `npm run dev` |
| 后端启动时警告 `[Supabase] Missing environment variables` | `backend/.env` 缺少 `SUPABASE_URL` 或 `SUPABASE_SERVICE_ROLE_KEY` |
| 浏览器报 CORS 错误 | 前端端口不在允许列表中（允许 3000、3001、5173），或者 `FRONTEND_URL` 配置错误 |
| 创建面试返回 500，`hint` 提示执行 migration | 本地库缺少 migration，执行 `npx supabase db reset` |
| 登录页没有本地登录按钮 | `VITE_LOCAL_SUPABASE` 不是字符串 `true`，或者修改后没有重启 Vite |
| 盖洛普结果没有解读文字 | 没有运行 `node scripts/seedGallupContent.js` |
| `npm ci` 失败 | Node 版本不是 22.x，或者 `package-lock.json` 与 `package.json` 不一致 |

## 鉴权

| 现象 | 原因与处理 |
|---|---|
| 401 `AUTH_TOKEN_INVALID` | token 过期或无效。前端会自动刷新一次；如果仍然失败，检查前后端连接的是不是同一个 Supabase 项目 |
| 前端报 `BACKEND_AUTH_REJECTED` | Supabase 认为会话有效，但后端拒绝了：通常是后端的 `SUPABASE_URL` 或 Service Role Key 与前端不属于同一个项目 |
| OAuth 回调页报错 | 授权码已经被用过（重复刷新回调页），或者 Supabase Auth 的 Redirect URL 中没有当前域名 |

## 面试

| 现象 | 原因与处理 |
|---|---|
| 403 `INSUFFICIENT_TOKENS` | 能量值不足，见[账户与计费](../03-技术与架构/通用机制/账户与计费.md) |
| 409 冲突 | `state_version` 过期（例如另一个标签页先提交了），客户端需要重新加载 |
| 练习首题一直在加载 | 出题超过 15 秒会使用本地备用题；如果仍然失败，前端会显示可以重试的错误 |
| 报告一直是 `processing` | 另一个请求持有 finalize 锁；查看 `interview_events` 中的 `finalize_*` 阶段和 `finalize_last_error` |
| `PGRST202` | 生产库缺少代码调用的 RPC，见[数据库迁移发布](数据库迁移发布.md#常见错误) |
| Gemini 429 / 配额错误 | 检查实际 `errorCode` / `failureType`；429 才归为限流或配额。报告使用独立备用列表及退避，见[报告生成](../03-技术与架构/面试报告.md#11-finalize-api)。同一项目的其他 Key 通常仍共享项目配额 |
| 文本 API 503 / 超时 | `gemini_unavailable` 表示暂时不可用，`gemini_model_timeout` 表示等待超时；不要根据旧事件名 `gemini_quota_exhausted` 就判断配额用完。按 requestId 检查 `gemini_text_attempt_failed` 的实际错误、耗时和预算。报告默认每个模型 30 秒、总计 90 秒 |

更多降级行为见[面试流程 · 失败与降级](../03-技术与架构/模拟面试/面试流程.md#18-失败与降级)。

## 语音

| 现象 | 原因与处理 |
|---|---|
| 完全没有声音 | 当前面试的声音来自 Gemini Live：先检查对话栏顶部是否有连接错误（点重试重连）、喇叭开关是否打开、`GEMINI_API_KEY` 和 `GEMINI_LIVE_MODEL` 是否有效，以及后端日志中 `/api/chat/live` 的错误 |
| 声音不对（音色、语言） | Live 音色由 `GEMINI_LIVE_VOICE_*` 或"面试官性格 + 面试语言"决定，见[环境变量](../02-开发指南/环境变量.md#gemini-模型) |
| Live 无法连接 | `start` 消息需要在 10 秒内完成鉴权；Origin 必须在允许列表中；可以用 `node scripts/checkLiveSocket.js` 在本地检查 |
| 浏览器没有弹出麦克风权限 | 需要 HTTPS 或 localhost；检查浏览器的站点权限设置 |

`/api/chat/tts` 一类的问题（机器人声音、配额 429 等）只会出现在兼容通道中，排查步骤见[实时语音与 TTS · 故障排查](../03-技术与架构/模拟面试/实时语音与TTS.md#10-故障排查)。

## 简历

| 现象 | 原因与处理 |
|---|---|
| `PDF_NO_TEXT` | 扫描版 PDF，没有可以选中的文字，需要先 OCR 或者直接粘贴文本 |
| `PDF_TOO_LARGE` | 超过 12 MB |
| `PDF_PASSWORD_PROTECTED` | 先解除密码 |
| 502 `Model returned invalid JSON` | 模型输出格式不对，重试，或者缩短简历 |

## 部署

| 现象 | 处理 |
|---|---|
| 后端工作流失败 | 按失败的阶段排查，见[后端部署 · 失败行为与排查](后端部署.md#9-失败行为与排查) |
| 后端部署成功但功能异常 | 先回滚 revision（[后端部署 · 回滚](后端部署.md#10-回滚)），再查日志 |
| 前端工作流失败或用户看到旧版本 | 见[前端部署 · 排查](前端部署.md#排查) |
| 部署后部分用户页面白屏 | 旧的 chunk 文件丢失，`lazyWithReload` 应该会自动刷新一次；确认静态目录中缺失的文件返回的是 404 而不是 HTML |
