## 正式发布

push 到 `main` 并且改动涉及 `frontend/**` 时触发。并发组为 `firebase-hosting-live`，不会取消正在进行的发布。

1. 检出代码，安装 Node 22（缓存 `frontend/package-lock.json`）；
2. 在 `frontend/` 中执行 `npm ci` 和 `npm run build`，构建失败就停止；
3. `FirebaseExtended/action-hosting-deploy@v0` 发布到 `live` 频道；
4. **验证**：从 `dist/index.html` 中取出入口文件名 `/assets/index-*.js`，然后每 5 秒请求一次线上首页，最多 12 次，直到线上引用的入口文件与本次构建一致，否则工作流失败。

构建使用 `frontend/.env.production`（已提交到仓库），其中只有可以公开的值：生产后端地址、Supabase URL 和 Anon Key。**不能加入任何服务端密钥。**

## PR 预览

同一仓库的分支发起 PR 并且改动涉及 `frontend/**` 时，构建后发布到临时预览频道，Action 会在 PR 中评论预览地址。来自 fork 的 PR 不会执行（拿不到 Secret）。预览不会影响正式站点。

注意：预览站点使用的是**生产后端和生产 Supabase**（同一份 `.env.production`）。另外，预览域名不在后端 CORS 允许列表中，需要调用后端的功能在预览环境中可能无法使用。

## 自定义域名

域名 `flowlab-career.com`，按[国内外双区部署方案](https://claude.ai/code/artifact/96345632-764d-490d-bc03-799e3047b4d0)规划：

| 主机名 | 指向 | 状态 |
|---|---|---|
| `global.flowlab-career.com` | 海外站前端（本 Firebase 项目） | 已启用 |
| `flowlab-career.com`（根域名） | 中国站，或上线前的“国内版 / Global”入口页 | 暂不绑定 |
| `api-global.`、`api.`、`db.` | 海外后端 / 中国站后端 / 中国站数据库 | 暂不绑定，后端仍用 `run.app` 地址 |

在 Firebase 控制台 → Hosting → 添加自定义域名，按提示到域名注册商添加 TXT（验证所有权）和 A/CNAME 记录；SSL 证书由 Firebase 自动签发，通常几分钟到 24 小时。换域名时需同步：

1. Cloud Run 环境变量 `FRONTEND_URL` 加入新域名（逗号分隔，旧地址保留）；
2. Supabase 控制台 → Authentication → URL Configuration：Site URL 改为新域名，Redirect URLs 加入 `<新域名>/auth/callback`；
3. Google / LinkedIn 的 OAuth 回调地址在 Supabase 域名下，不用改；Google OAuth 同意屏幕的“已获授权的网域”建议加入 `flowlab-career.com`。

## Hosting 规则（`firebase.json`）

### 缓存

| 匹配规则 | Cache-Control |
|---|---|
| `**`（默认，包括 `index.html`） | `no-cache, no-store, must-revalidate` |
| `**/*.{js,css,png,jpg,jpeg,gif,svg,webp,woff,woff2}` | `public, max-age=31536000, immutable` |

带 hash 的资源可以长期缓存，`index.html` 每次都重新获取，所以发布后用户刷新一次就能拿到新版本。

### SPA 回退与 404

```json
{ "source": "!/@(assets|avatars|images|logos)/**", "destination": "/index.html" }
```

- 除了 `/assets/`、`/avatars/`、`/images/`、`/logos/` 这四个静态目录，其他路径都回退到 `index.html`，交给 React Router 处理。
- 这四个目录下**不存在的文件会返回真正的 404**，而不是 `index.html`。这样，部署后旧的 chunk 文件丢失时，浏览器会得到明确的加载错误，`lazyWithReload` 捕获错误后会自动刷新一次页面，拿到新的入口文件。
- 在 `public/` 下新增顶层静态目录时，要同步修改这条规则，否则缺失的文件会返回 HTML。

## 手动部署（应急）

正常情况下不需要手动部署。如果必须手动部署，需要有 Firebase 项目权限：

```bash
cd frontend
npm ci && npm run build
npx firebase-tools deploy --only hosting --project aiinterviewer-491711-7b1cf
```

手动部署会覆盖 `live` 频道，下次 CI 发布时又会被覆盖回来，所以修复也要尽快合并到 `main`。

## 回滚

- **Firebase 控制台** → Hosting → 发布记录 → 选择之前的版本 → 回滚。立即生效。
- 或者 revert 有问题的提交并 push 到 `main`，由 CI 重新发布。

## 排查

| 现象 | 排查方向 |
|---|---|
| 构建失败 | 在本地 `frontend/` 中执行 `npm ci && npm run build` 复现 |
| 部署步骤失败 | Service Account Secret 是否有效、有没有 Hosting 权限 |
| 验证步骤失败 | CDN 传播比较慢，可以手动重跑；或者 `index.html` 的缓存头被改掉了 |
| 用户看到旧版本 | `index.html` 是否仍然是 `no-cache`；浏览器里是否有 Service Worker（目前没有注册） |
| 资源返回 HTML 而不是 404 | 资源目录是否在回退规则的排除列表中 |
