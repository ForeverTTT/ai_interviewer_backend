# 本地开发

> 状态：现行 · 最后核对：2026-10-01

本文说明如何在本机同时运行前端、后端和（可选的）本地 Supabase。变量的含义见[环境变量](环境变量.md)，测试方法见[测试](测试.md)。

## 前置要求

- Node.js 22.12 或更新的 22.x 版本（后端 `package.json` 的 `engines` 和 CI 都使用 22）。
- 使用本地 Supabase 时，需要先启动 Docker Desktop。
- 本项目是 Node.js 项目，不使用 Python `venv`。依赖安装在各自目录的 `node_modules` 中，版本由 `package-lock.json` 锁定；请用 `npm ci`，不要用 `npm install`。

## 两种后端数据源

| 方式 | 适用场景 | 需要的配置 |
|---|---|---|
| 云端 Supabase 开发项目 | 只改前端或业务逻辑，不涉及 Schema | 云端项目的 URL、Service Role Key、Anon Key |
| 本地 Supabase | 修改 migration、RLS、RPC，或需要隔离的测试数据 | `npx supabase start` 输出的本地 URL 和密钥 |

不要让本地开发环境连接生产 Supabase 写入测试数据。

## 1. 后端

从仓库根目录执行（PowerShell）：

```powershell
cd backend
npm ci
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

macOS / Linux：

```bash
cd backend
npm ci
test -f .env || cp .env.example .env
```

编辑 `backend/.env`，至少填写 `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY` 和 `GEMINI_API_KEY`，然后启动：

```bash
npm run dev     # nodemon 热重载
# 或
npm start       # 不带热重载
```

后端默认监听 `http://localhost:5000`。检查服务是否正常：

```bash
curl http://localhost:5000/api/health
```

`.env` 的路径是相对于 `backend/src/config/env.js` 解析的，因此从仓库根目录或 IDE 启动也能读取到 `backend/.env`。

## 2. 前端

另开一个终端：

```powershell
cd frontend
npm ci
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

编辑 `frontend/.env`：

- 填写 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_ANON_KEY`；
- 让 `VITE_BACKEND_URL` 指向 `http://localhost:5000`，并**删除或注释掉 `VITE_API_URL`**，因为它的优先级更高。

然后启动：

```bash
npm run dev
```

开发地址是 `http://localhost:3000`。Vite 虽然配置了 `/api → localhost:5000` 的代理，但客户端代码使用的是配置的完整后端地址，所以不能指望代理来纠正错误的环境变量。

## 3. 本地 Supabase（可选）

`backend/supabase/` 包含本地认证配置、全部 migration、RLS、头像存储桶和盖洛普题目种子数据。在 `backend/` 目录执行：

```bash
npx supabase start                          # 启动本地容器
npx supabase db reset                       # 按顺序应用全部 migration 并执行 seed.sql
npx supabase db lint --local --level warning
npx supabase status                         # 查看本地 URL 和开发密钥
```

本地服务地址：

| 服务 | 地址 |
|---|---|
| API | `http://127.0.0.1:54321` |
| 数据库 | `postgresql://postgres:postgres@127.0.0.1:54322/postgres` |
| Studio | `http://127.0.0.1:54323` |
| 测试邮件 | `http://127.0.0.1:54324` |

把 `status` 输出的 API URL、`service_role key` 填进 `backend/.env`，把 API URL 和 `anon key` 填进 `frontend/.env`。

### 本地登录

在 `frontend/.env` 中设置 `VITE_LOCAL_SUPABASE=true` 后，登录页会显示本地账户按钮，隐藏 Google / LinkedIn 按钮。第一次点击时会在本地 Supabase 自动注册开发账户（默认 `local@example.com` / `localdev123`，可以用 `VITE_LOCAL_EMAIL`、`VITE_LOCAL_PASSWORD` 修改），之后直接登录。

### 盖洛普分析文案

`seed.sql` 只写入 20 道盖洛普题目。分析文案表 `gallup_analysis_content` 需要另外运行脚本填充（脚本使用 `backend/.env` 中的 Supabase 配置）：

```bash
node scripts/seedGallupContent.js
```

### 停止

```bash
npx supabase stop
```

## 4. 开发脚本

| 脚本 | 用途 |
|---|---|
| `backend/scripts/checkLiveSocket.js` | 用本地账户登录，并对 `/api/chat/live` 做一次 WebSocket 连通性检查。它读取 `frontend/.env` 中的 Supabase 配置，可以传入语言参数，如 `node scripts/checkLiveSocket.js Deutsch` |
| `backend/scripts/seedGallup.js` | 写入盖洛普题目（与 `seed.sql` 的作用相同，用于已有数据库） |
| `backend/scripts/seedGallupContent.js` | 写入盖洛普分析文案 |

## 5. 用 Docker 运行后端

用于在本地验证生产镜像。`backend/.dockerignore` 会排除本地 `.env`。

```bash
cd backend
docker build -t interviewde-backend .
docker run --rm -p 8080:8080 --env-file .env -e PORT=8080 interviewde-backend
```

启动后访问 `http://localhost:8080/api/health`。
