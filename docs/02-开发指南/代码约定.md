# 代码约定

> 状态：现行 · 最后核对：2026-10-01

这里只记录不读代码就容易违反的约定。整体结构见[系统总览](../03-技术与架构/系统总览.md)。

## 仓库与目录

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `backend/src/routes/` | 每个 `/api/<资源>` 一个 Router，负责参数校验、鉴权和组装响应 | 大段业务逻辑，放到 `lib/` |
| `backend/src/lib/` | 业务逻辑、Supabase / Gemini 封装、可以单测的纯函数 | Express 的 `req` / `res` |
| `backend/src/agents/` | LangGraph 面试图和 Prompt 工具 | |
| `backend/src/config/` | 策略配置的唯一来源，如 `interviewerTypes.js`、`interviewerStyles.js` | 密钥 |
| `backend/src/live/` | WebSocket（Gemini Live） | |
| `backend/data/prompts/` | 运行时 Prompt 模板 | 说明文档 |
| `backend/data/knowledge_base/` | 运行时知识库 JSON | |
| `backend/supabase/migrations/` | 数据库 Schema 变更 | 测试数据 |
| `frontend/src/pages/` | 路由级页面 | |
| `frontend/src/components/` | 可复用组件；`app/` 是登录后外壳，`brand/` 是品牌视觉，`landing/` 只给落地页用 | |
| `frontend/src/lib/` | 与 UI 无关的客户端工具 | |
| `docs/` | 供人阅读的文档，结构见 [docs/README.md](../README.md) | 运行时文件 |

前端和后端是两个独立的 npm 项目，各自有 `package.json` 和 `package-lock.json`，仓库根目录没有 workspace。

## 后端

- **ES Module**：`"type": "module"`，导入相对路径时必须带 `.js` 后缀。
- **入口先加载环境变量**：新的入口文件或脚本如果用到环境变量，先 `import './config/env.js'`（或导入已经导入它的 `lib/supabase.js`）。
- **鉴权**：业务路由都加 `requireAuth`，从 `req.user.id` 取用户，不能信任请求体里的 `user_id`。查询、更新、删除都要同时带上 `user_id` 条件。
- **数据库客户端**：需要遵守 RLS 时，用 `supabaseForUser(req.accessToken)`；需要越过 RLS 时（如扣费、写入事件），用 Service Role 的 `supabase`，同时由代码保证只操作当前用户的数据。
- **有副作用的接口要幂等**：接受 `idempotencyKey`（或 `Idempotency-Key` 请求头），重试时返回第一次的结果。面试相关的写操作还要校验 `state_version`（乐观锁）。详见[面试流程 · 一致性、幂等与并发](../03-技术与架构/模拟面试/面试流程.md#12-一致性幂等与并发)。
- **扣能量值**：使用 `checkTokens` + `deductTokens`，或在 RPC 里原子扣除。规则见[账户与计费](../03-技术与架构/通用机制/账户与计费.md)。
- **错误响应**：返回 `{ error, code? , requestId? }`，不能把第三方错误对象、密钥或内部 URL 透传给客户端。
- **日志**：使用 `lib/observability.js` 的 `logStructured`，它会自动带上 request ID 并脱敏。
- **Gemini 调用**：通过 `lib/geminiText.js` 的 `invokeGemini`，这样能自动获得配额降级（换模型重试一次）和 Vertex 后备。

## Prompt 模板与知识库

- 代码用 `loadPrompt('<name>')` 读取 `backend/data/prompts/<name>.md`，用 `loadKnowledge('<name>')` 读取 `backend/data/knowledge_base/<name>.json`。**文件名就是接口**，改名必须同时修改所有调用方。
- 模板变量写作 `{{VARIABLE_NAME}}`（全大写下划线），由 `renderPrompt(template, vars)` 替换；没有提供的变量会被替换成空字符串，不会报错，所以新增变量时要检查调用方是否都传了值。
- `runtimeDataPaths.test.js` 会检查这两个目录可以读取；移动目录后需要运行 `npm test`。
- 各模板的用途见[agent与Prompt](../03-技术与架构/模拟面试/agent与Prompt.md#7-prompt-模板体系)。
- 注意：除 `motivation_letter.md` 外，`data/prompts/` 下的模板和 `data/knowledge_base/` 只被 LangGraph（SSE 兼容通道）使用，**当前面试并不经过它们**。正式模拟、练习和报告的 Prompt 内联在代码中，修改时要改对地方，见[agent与Prompt](../03-技术与架构/模拟面试/agent与Prompt.md)开头的对照表。

## 数据库 Migration

- 文件名格式：`YYYYMMDDHHMMSS_<snake_case_说明>.sql`，放在 `backend/supabase/migrations/`。
- **不修改已经应用到生产的 migration**，有变更就新建一个。
- 新表必须 `enable row level security` 并写清楚策略；只允许后端写入的表，不要给 `authenticated` 角色写权限。
- 修改 RPC 签名时，要先把 migration 发布到生产，再部署调用新签名的后端，否则会出现 `PGRST202`。流程见[数据库迁移发布](../05-运维/数据库迁移发布.md)。
- 新增或修改表后，同步更新[数据库参考](../04-参考/数据库.md)。

## 前端

- **请求后端**：使用 `lib/authenticatedFetch.js`。它会附加 Bearer token，遇到 401 时刷新一次 token 再重试，并且只有 Supabase 也确认会话失效时才清除登录状态。后端地址统一通过 `getBackendBaseUrl()` 获取。
- **页面懒加载**：`App.jsx` 中的页面用 `lazyWithReload(() => import(...))` 加载。部署后用户如果还持有旧的入口文件，加载失败时会自动刷新一次。
- **状态管理**：不使用全局状态库。面试业务状态以服务端为准，前端不要把 localStorage 当作业务数据的来源。
- **能量值变化**：余额变化后派发 `window.dispatchEvent(new Event('tokensChanged'))`，让侧栏刷新显示。

## 国际化（i18n）

- 界面文案放在 `frontend/src/locales/{zh,en,de}.json`，三个文件的 key 结构必须一致。
- 回退语言是 `zh`：某个 key 在德语里缺失时，德语用户看到的是**中文**，而不是英文。
- 新增文案时三种语言一起加。不要在组件里写死用户可见的文字。
- 界面语言（i18next）和面试语言（`English` / `Deutsch` / `Chinese`，创建面试时选择）是两个独立的设置。
- 当前差异（2026-10-01 核对）：`de.json` 比另外两种语言少 10 个 `profile.energy*` / `profile.rechargeBtn` key，但这些 key 没有被任何页面使用，不影响显示。`zh.json` 中有重复的命名空间（`notes`、`growthSprint`、`dashboard.growth`），后出现的会覆盖先出现的。
