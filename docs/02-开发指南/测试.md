## 后端单元与行为测试

```bash
cd backend
npm test        # 等同于 node --test，自动运行 test/*.test.js
```

使用 Node 内置的 `node:test` 和 `node:assert/strict`，不需要额外依赖，也不需要连接数据库或 Gemini。

| 文件 | 覆盖内容 |
|---|---|
| `interviewSessionStore.test.js` | 多场面试隔离、重启后恢复 checkpoint、乐观锁拒绝过期写入、幂等重放、重连上下文范围 |
| `interviewLearning.test.js` | 四种难度策略、四级提示、面试官类型约束、练习结束条件、反馈评分、RAG 排序、能力矩阵、Gemini 失败时的备用题 |
| `interviewerStyles.test.js` | 面试官风格归一化、安全边界与音色选择 |
| `observability.test.js` | request ID 归一化、密钥脱敏、配额错误降级到 Flash-Lite、报告重新生成规则 |
| `geminiFallback.test.js` | 练习模型多级兜底、候选去重、鉴权错误立即停止、候选耗尽、总预算取消及列表配置 |
| `geminiText.test.js` | 总超时覆盖慢速回调，超时后回调返回不会启动模型请求 |
| `growthCenter.test.js` | 五维准备度、趋势判断、训练节奏统计口径 |
| `offerSprint.test.js` | 冲刺阶段边界、周计划上限、48 小时清单、提醒渠道、周报 |
| `runtimeDataPaths.test.js` | `data/prompts` 和 `data/knowledge_base` 在当前目录结构下可以读取 |
| `interviewLiveSocket.test.js` | 上游正常关闭、GoAway、错误脱敏、音频计数、主动结束及连接建立期间关闭 |
| `liveTurnPersistence.test.js` | 最新状态版本、并发保存冲突重试、幂等重放、锁定状态与正式面试截止保护 |

新增测试文件命名为 `*.test.js` 并放在 `backend/test/`，`node --test` 会自动发现。

前端 `npm test` 自动发现测试文件。新增的 `test/useGeminiLiveInterview.test.js` 使用模拟 WebSocket、计时器和 hook 调度器执行真实 hook 代码，覆盖关闭通知、重连上限、主动停止及非致命保存错误。它不替代真实浏览器的麦克风权限和音频播放回归。

## 数据库事务化验收

需要先启动本地 Supabase 并执行 `npx supabase db reset`（见[本地开发](本地开发.md#3-本地-supabase可选)），库里至少要有一个用户（用本地账户登录一次即可）。每个脚本都在一个事务中运行，结束时回滚，不会留下测试数据。

| 脚本 | 覆盖内容 |
|---|---|
| `test/sql/interview_sessions_integration.sql` | 同一用户多场面试互相隔离、创建和扣费的幂等性、乐观锁冲突、练习模式全部动作、正式模式截止时间与限制、Adaptive 难度和评分证据 |
| `test/sql/billing_authorization.sql` | 以已登录用户身份（`authenticated` 角色 + JWT）尝试修改余额和打卡状态、插入自带余额的资料行、扣别人的能量值、免费创建面试，这些操作都必须被拒绝；同时确认资料字段仍然可以写，Service Role 仍然可以扣费 |

```bash
cd backend
for f in test/sql/*.sql; do
  docker exec -i supabase_db_ai_interviewer_backend \
    psql -U postgres -d postgres -v ON_ERROR_STOP=1 < "$f" || break
done
```

PowerShell 不支持 `<` 重定向，可以这样写：

```powershell
Get-ChildItem test/sql/*.sql | ForEach-Object {
  Get-Content $_ -Raw | docker exec -i supabase_db_ai_interviewer_backend psql -U postgres -d postgres -v ON_ERROR_STOP=1
}
```

修改 migration 或 RPC 后必须重新运行。

## 前端构建检查

```bash
cd frontend
npm run build      # 输出到 dist/
npm run preview    # 本地预览生产构建，只用于检查，不能当生产服务器
```

前端 `npm test` 运行 `test/dashboardStore.test.js`，覆盖复盘先于成长数据显示、后台刷新失败保留缓存、并发请求复用、用户隔离、退出后的迟到响应和删除同步。它不覆盖浏览器视觉、React 页面交互或麦克风，需要结合构建检查及人工回归。

## 人工回归清单

涉及面试流程的改动，上线前至少覆盖以下场景（需要同时启动后端和 Supabase）：

- 练习模式：暂停 / 恢复、四级提示、笔记、多次作答、掌握和跳过；
- 正式模式：不能暂停；关闭页面后服务端仍在计时；截止时正在作答可以答完最后一题；
- 打开两个标签页分别进行不同面试，确认不会串线；
- 刷新 `/interview/:id`，确认恢复到同一场面试；
- Gemini Live 断线重连后只恢复当前 `interviewId` 的上下文；
- 中、英、德三种界面语言下，新增文案都能正常显示；
- 浏览器麦克风权限和真实设备上的音频质量。

更完整的面试验收标准见[面试流程 · 测试与验收](../03-技术与架构/模拟面试/面试流程.md#20-测试与验收)。
